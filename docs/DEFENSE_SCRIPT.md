# 答辩稿（DEFENSE_SCRIPT）

> 适用时长：2–3 分钟。语速适中，配合页面演示。

---

**各位老师好，我演示的作品是 CampusShelf 校园学习资源交易平台。**

**【为什么选这个主题】**
大学生常有二手教材、课程笔记、考研资料、实验报告模板、电子书和学习用品的交易与共享需求，
但综合电商平台缺少校园垂直入口。我们从开源 Bookstore 二次开发，把它升级为面向校园的资源平台，
更贴近真实使用场景。

**【系统功能】**
平台有三条主线：
第一，前台资源流——首页 Hero 搜索、6 大分类的资源列表（支持关键词、价格区间、新旧程度筛选和分页）、
资源详情（收藏、加入购物车、评论评分）；
第二，用户中心——我的发布、我的收藏、我的订单、最近浏览，以及注册登录和搜索历史；
第三，管理后台——资源审核、用户/订单/评论管理，以及用图表展示运营数据。

**【技术栈】**
后端用 Node.js + Express + Handlebars，沿用原项目降低门槛；
数据层默认用 JSON 文件存储，做到 Windows 一键运行、零外部依赖；
前端是原生 JavaScript，图表用 Chart.js。

**【界面设计】**
我们做了统一的校园清新风格：卡片式布局、圆角、阴影、统一主色，并且手机、平板、桌面都做了响应式适配。

**【性能优化】**
做了几件真实可讲的事：所有资源图用 `loading="lazy"` 懒加载；搜索框加了 300 毫秒防抖，
避免每次按键都请求；列表分页每页 8 条；搜索历史、最近浏览、主题偏好用 localStorage 缓存；
搜索和列表切换时有加载态提示。

**【Redis 和 Nginx 的作用】**
这是两个加分项，且都不影响基础功能。
Redis 用于缓存热门资源、搜索结果和排行榜，`utilities/cache.js` 会自动探测——
没有 Redis 时自动降级为内存缓存，控制台会打印当前模式，保证项目永远能跑。
Nginx 作为反向代理，开启 gzip 压缩和静态资源缓存，用于演示部署与性能优化能力。

**【项目创新点】**
一是场景升级，从通用书店变成校园垂直平台；二是可运行性强，摆脱了原项目对 MongoDB 和
Google API 的强依赖；三是缓存降级设计，体现工程健壮性；四是前台、用户中心、管理后台形成完整闭环。

**【总结】**
CampusShelf 是一个功能完整、界面美观、可在 Windows 本地直接运行、并具备缓存与部署优化思路的
学生实践作品。我的演示到此结束，谢谢老师！
